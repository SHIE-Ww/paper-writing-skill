# 按需使用的任务模板

仅在需要组织输入时选择相应模板。方括号由作者填写；缺少材料不得虚构。

## 故事主线与创新点

```text
请根据我的初始动机 [动机]、失败案例 [案例]、相关工作 [文献]、方法模块 [模块] 和实验 [结果]：
1. 判断适合“老问题，新方法”还是“发现新问题”；
2. 将问题拆解为可验证的挑战，建立“挑战—方法—证据”关系；
3. 精炼核心贡献；
4. 站在审稿人立场提出最有力的质疑，并标注待验证内容。
不新增事实，暂时不要代写全文。
```

## 摘要或章节结构

```text
目标发表渠道：[会议/期刊]；已确定故事线：[主线]；参考论文：[文章或摘录]。
请比较参考论文的叙事结构，提出本论文 [章节] 的小节/段落功能和逻辑顺序。
跨渠道比较用篇幅比例而非字数。只借鉴写作结构，不复制内容。
```

## 逐段修改

```text
段落目标：[本段要回答的问题]；已定稿摘要/主线：[上下文]；
原文：[段落]。
只修改此段，检查事实范围、逻辑跳跃、前后衔接与表达；
保留我的技术判断和术语。给出修改版，以及最多三条关键改动理由。
```

## 反过度防御润色

```text
逐句检查 [文字]。删除不提供信息的过渡与模板句；
核心判断前置，将模糊限定替换为明确条件，只回应真实质疑。
不要为了简洁删除证据所要求的限制；不需要修改的句子保持原样。
```

## 方法框架图

```text
方法说明：[摘要、引言、方法]；模块与连接：[结构]；当前图（可选）：[图]。
先给出 5–6 种不同的框架图布局及各自取舍；
从整体清晰度、信息流正确性和色觉友好性推荐一版。
给出 PowerPoint 中可编辑的分区、形状与连接线重绘顺序。
若细节缺少依据，指出而不是自行补充模块。
```
