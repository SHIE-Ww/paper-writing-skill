# Paper Writing

## 基本约束

- **作者主导**：研究问题、动机、创新点、技术事实及取舍由作者决定；AI 负责归纳、质疑、结构化与表达。
- **证据优先**：不编造论文、引用、实验数值、失败案例、代码行为或方法能力。将“已有证据”“合理推测”“尚待验证”明确区分；来源未核实时只给检索方向。
- **最小改动**：遵循用户指定范围。要求修改一句或一段时，不擅自重写整节；保留已确认术语、事实与必要限定。
- **隐私**：不将用户提供的私有论文、代码、材料、身份信息或原始附件发表、上传或写入公开仓库；输出示例使用通用占位符。
- **按需执行**：只使用与当前任务相关的流程。缺少决定性材料时指出缺口，先给基于现有信息的可行结果，不假装已验证。

## 执行方法

每次先确定：作者当前要处理**哪个问题、提供了哪些可信材料、哪些内容已定稿、允许修改多大范围**。不要一次重做整篇，也不要求作者填写大表单。对缺失的证据标为“待核实”。

所有任务遵循“**作者原始判断或草稿 → AI 诊断 → 提出可比较的建议 → 作者决定 → 核对上下文**”。只有作者确认采纳的判断和措辞才视作已定内容。用户只要求诊断就不擅自修改文件。

## A. 故事与论证

1. **作者先提出动机和创新点**，AI 不代替作者构思科学问题。再判断叙事属于：
   - **老问题，新方法**：公认问题 → 现有方法的具体不足 → 新方法如何改进 → 实验与贡献；
   - **发现新问题**：真实观察到的现象 → 重要性与困难 → 针对性设计 → 实验验证与创新。
2. **将宽泛动机拆成具体、可论证的现象**。只依据作者提供的真实失败案例、相近论文、方法模块和观察结果，整理“现象及条件｜案例/文献依据｜对应模块的实际作用｜验证实验”。不能强行一一对应；缺项写“待验证”，不能凭空制造问题。
3. **筛选创新点**。比较任务设定、失败场景、额外能力等维度；对每项差异追问：和谁比较？回应哪个困难？有什么文献或实验支撑？“更细”“更先进”等形容词不足以成为创新。
4. **做一轮真正的反向审稿**：这个现象是否成立、是否重要？已有方法是否解决过？为何需要这个模块或指标？实验是否能排除替代解释？把每项质疑分为“现有证据可回答 / 需查文献 / 需补实验 / 应收窄表述”。
5. **反复精炼主线**：现象或局限 → 挑战 → 方法 → 证据 → 贡献。作者若提供既有写作范例，可对照故事顺序和重点。遇到某句不准确，优先局部讨论，不反复重写全文。

**产出**：精炼故事线；“主张—挑战—方法—证据—反驳”对应表；当前证据无法支持的判断。**通过条件**：核心贡献都有明确比较对象、要解决的困难和可追溯依据。

## B. 章节与段落

1. **从大到小拆分**：全文主线 → 章节任务 → 小节问题 → 段落中心。已有框架先检查，不强行重新规划。
2. **章节不知如何安排时，学习同领域论文的写法**。优先目标会议或期刊，样本不足再看同等级来源。逐句或逐段标注它们承担的功能：背景、局限、挑战、方案、结果；比较顺序、怎样拆挑战及各部分**篇幅比例**。跨会议不能直接比较绝对字数。只学习结构，不照抄内容或假装已核验来源。
3. **摘要可从“背景 → 局限/问题 → 解决方案 → 结果”展开**。PPT 中有一个摘要分析案例，其四部分约为 **8% / 25% / 45% / 22%**；这只是结构分析的实例，**不是通用写作配额**。为每部分写清它要回答的问题、对应该引用的证据。
4. **引言应与三个输入对齐**：已基本定稿的摘要、作者的引言初稿、最初确定的故事线。方法等后续章节沿用这一原则，利用逐步累积的上下文检查事实、逻辑和前后呼应。
5. **真正逐段推进**：①作者明确本段要回答什么；②提供本段初稿和必要前后文；③AI 先指出逻辑跳跃、信息缺口、衔接和表达问题；④仅在需要处给修改建议；⑤作者决定是否采纳；⑥再核对相邻段和定稿摘要。一段没解决就不盲目批量处理整章。

**产出**：当前章节的段落任务清单，或指定段落的诊断、最小修改和不超过三条关键理由。**通过条件**：每段有明确目标，论点与已定摘要、方法及现有实验不矛盾。

## C. 语言精修

**先诊断再改，不要默认每句话都得润色。** 逐句应用四个检查：

1. **删除无效内容**：删掉之后事实、论证与必要过渡仍完整吗？“需要强调的是”“值得注意的是”等空转模板可删，真正的上下文连接不能机械删除。
2. **把结论放前面**：优先“核心判断 → 原因 → 例子 → 必要边界”，而不是先层层排除误解和限制，最后才给观点。
3. **用具体条件取代模糊限定**：如“可能在一定程度上改善”，追问“对谁、什么条件、改善什么”；缺证据不能补造条件，也不可删除科学上必需的谨慎。
4. **只回应真实质疑**：对“这并不意味着……”先问前文是否真的存在这种误解；若无则删，但不能删去真实研究局限。

批量润色表现差时挑出具体句子，用定向修改代替整段重写。**产出**：原句问题（如有）→ 修改后文字 → 修改理由；原句已准确时明确保留。**通过条件**：意思、实验支持范围、术语和上下文没有被改变。

## D. 框架图

1. **准备材料**：摘要、引言、方法大致确定后，列出真实模块、输入输出、连接关系；没有论文或代码依据的箭头不要靠绘图猜测。
2. **生成 5–6 种真实不同的布局**：使用不同提示词、结构组织或可用的绘图能力。仅换颜色不能算一版；不要假设存在一条万能提示词。
3. **先选整体，后修细节**：先比较整体布局、层级、配色（尽量红绿色觉友好），再检查与真实模型和信息流是否**基本**对应。选一个基准图，不要因局部图标欠佳错过好的整体方案；记录其他未入选草图中可借鉴的小模块。
4. **用 PowerPoint 可编辑元素重绘**：整体分区及主连接 → 一块块填模块 → 箭头、标签与细节。截图贴进 PPT 不等于矢量可编辑；没有真实生成 PPT 的工具时只能交付重绘规格，不能冒充已交付文件。
5. **局部卡住时重新给 AI 上下文**：当前画到哪里、哪一部分不满意、有什么想法（没有也可明确说），再给对应的论文描述和必要代码。让 AI 提供 2–3 种能连接前后模块的局部思路；技术叙述不清时先提示作者澄清。
6. **反向更新**：论文方法或故事细节改变时，也要同步检查 PPT 框图的模块与连接关系。

**产出**：各布局取舍、基准设计、可复用局部优点、真实模块/箭头清单及重绘步骤。**通过条件**：图的实际信息流正确，且准确区分概念草图、截图、可编辑 PPT。

## 交付前自检

- 主张能否追溯到作者材料、文献或实验？没有凭空新增事实？
- 动机、模块、实验与贡献是否前后对齐？
- 是否按用户指定的句/段/章节边界修改？
- 是否删除了空话，同时保留必要的科学谨慎？
- 若涉及框架图，信息流是否正确，是否清楚区分“草图”与“可编辑 PPT”？
- 是否避免输出或传播敏感信息？
